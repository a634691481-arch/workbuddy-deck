# 教训记录

## 2026-10-30 切换账号把目标账号会话删光
- **模式**：把「目标侧看起来已经有了」当成写入成功（alreadyLinked 计入成功数），紧接着执行物理删除 → 数据清零。
- **规则**：破坏性动作（删除/覆盖/替换）前必须有硬门槛：**本次真实写入条数 > 0**，且只统计本次新增。
- **规则**：替换类操作不能复用「旧关联/旧快照」做成功判定——那批东西正是要被删的。
- **规则**：前端不能只看 `replaced===false`；`copied===0` 同样是失败，必须显式报错。
- **规则**：先备份再动手（DB 快照 + 清单日志），恢复脚本按关联组反查副本，成本最低。

## 2026-10-30 补充：复制「部分成功」也不许删
- **模式**：只挡 `copied == 0` 仍有漏洞——源 74 条里 5 条缺正文时，复制 69 条 + 删光旧 72 条，结果少 5 条且无法补齐。
- **规则**：替换式同步必须 `copied == 源会话数` 且 `errors == 0` 才允许删除；否则 fail-closed，保留旧会话并在 reason 里说明「部分会话复制失败」。
- **规则**：前端报错要带数字（复制 N/M、失败 K），"未完成"三个字不足以判断。

## 2026-10-30 名字/定位建议前必须先查生态占用
- **模式**：给开源命名建议时只凭"GitHub 搜索流量靠关键词"的通用经验，推荐 `quota-deck`，忽略了目标生态内的实际搜索词就是品牌名。
- **数据**：GitHub `workbuddy in:name` 共 3190 个仓库，头部 `workbuddy2api-panel` 4638★、`WorkBuddyGuide` 3659★、`workbuddy-manager` 2174★、`workbuddy-switch` 1630★。
- **规则**：命名/定位类建议，先跑一次 `api.github.com/search/repositories?q=<词>+in:name&sort=stars`，看头部 star 与命名模式，再下结论。品牌词有高星同类群 = 受众搜索词是品牌，不是通用词。
- **规则**：有上游/衍生项目（本例 `workbuddy-switch` 1630★）时，名字必须能区分，且 README 首屏声明关系，否则被视为抢星或抄袭。
