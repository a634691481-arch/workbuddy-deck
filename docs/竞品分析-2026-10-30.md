## 0. 结论摘要

| # | 结论 | 依据 |
| --- | --- | --- |
| 1 | **"账号切换"已是红海**，14 个样本里 11 个做切换，本项目在该维度不构成差异 | 见 §2 |
| 2 | **真正的分水岭是"切换之后"**：事务安全 + 用量预测 + 成本折算，这三件事大厂工具几乎全做，本项目全缺 | 见 §3 矩阵 |

| 5 | 不建议扩到「30-50 工具统一口径」，会摊薄现有定位且工程成本极高 | 见 §7 Non-goals |

## 4. 缺口清单（按"不做会怎样"排序）

| 排序 | 缺口 | 不做的后果 |
| ---: | --- | --- |
| 1 | 切换无事务边界、无写后校验 | **已发生两次真实数据丢失**（`lessons.md` 2026-10-30 两条） |
| 2 | 无用量预测 | 用户只知"余额 1200"，不知"周五就断"，无法提前调度 |
| 3 | 无成本折算 | Token 数对非技术用户无决策意义；无法横向比较账号价值 |
| 4 | 配额窗口未建模 | "5 小时额度"与"积分包到期"混在一个数字里，误判 |
| 5 | 无健康评分 | 20 个账号时无法一眼扫出"哪个号快废了" |
| 6 | 无切换历史 | 出事无法回溯"谁在什么时候换了什么、当时余额多少" |
| 7 | 无限流驱动切换 | 撞墙后要手动换号 + 手动续接会话 |
| 8 | 无导出 / 环比 | 数据只能看不能带走，无法做月度复盘 |
| 9 | 托盘无配额读数 | 常驻价值未兑现，用户仍需开窗 |
| 10 | 无多设备聚合 | 笔记本 + 台式各算各的，总量失真 |

## 5. 优先级与理由

评分口径：`价值 = 决策价值(1-5) × 事故成本(1-5) ÷ 实现成本(1-5)`。事故成本 ≥4 且已实际发生 → 直接进 P0。

| 优先级 | 事项 | 价值 | 成本 | 理由 |
| :---: | --- | :---: | :---: | --- |
| **P0-1** | 切换事务化 + 写后身份校验 | 25 | M | 两次事故；用户信任是这类工具的唯一护城河 |
| **P0-2** | 用量预测与耗尽预警 | 20 | S | 把"余额多少"升级为"还能撑几天"，是本品类最高频问题 |
| **P0-3** | 成本折算（等价金额） | 20 | S | 价目表可离线内置，一次投入长期复用；直接提升统计页说服力 |
| **P1-1** | 配额窗口统一建模 + 倒计时 | 16 | M | 为 P0-2 提供正确分母，否则预测口径错 |
| **P1-2** | 账号健康评分 | 12 | S | limits/error_log/refresh 三处数据已在手，纯聚合 |
| **P1-3** | 切换历史与审计 | 11 | S | 与 P0-1 同一批改动顺手落地；LogsView 加一源即可 |
| **P1-4** | 导出 CSV/JSON + 周期对比 | 10 | S | 低成本高感知；环比是"数据饱满"的最短路径 |
| **P1-5** | 托盘配额读数 | 8 | S | 托盘已存在，只加 tooltip/title |
| **P1-6** | 限流驱动自动切换 | 9 | L | 价值高但会打断会话，必须 opt-in + 冷却 + 续接，风险等级最高 |
| **P1-7** | 预算/额度预警 | 6 | S | 积分制下只能做预警，不做硬停 |
| **P2-1** | 并发多开隔离 | 12 | XL | 与"共享登录态"定位有张力，需产品决策先行 |
| **P2-2** | 多设备聚合 | 8 | L | 需引入同步通道，打破"零网络"约定 |
| **P2-3** | 分支 / PR 归因 | 6 | M | 仅对重度用户有意义 |
| **P2-4** | 分位统计（P50/P90/P95） | 4 | S | 锦上添花，需 ≥30 天样本 |
| **P2-5** | 供应商/端点切换、MCP 治理 | 3 | L | cc-switch 领地，进入即正面竞争 |

## 6. 落地方案

> 遵循本项目三宿主透传范式：`core 模块 → src-tauri/src/commands.rs（薄包装）→ lib.rs 注册 + api.ts ROUTES + 视图`。
> 全部新增能力**不新增网络请求**（沿用 `limits.rs` / `official_usage` 已有通路），保证离线可用。

### P0-1 切换事务化

**现状**：`modules/switch.rs` 直写认证文件；`auth_file::backup_auth_file` 与 `session.rs::backup_workbuddy_db` 各自备份，无统一提交点；无写后身份校验。

**方案**
1. 新增 `crates/wb-switch-core/src/modules/txn.rs`
   ```rust
   pub struct TxnPlan { items: Vec<WriteItem> }   // path, prev_hash, payload
   impl TxnPlan {
       pub fn plan(...) -> Result<Self, String>;
       pub fn commit(&mut self) -> Result<TxnReport, String>;  // tmp + fsync + rename，逐项
       pub fn rollback(&mut self) -> Result<(), String>;      // 逆序还原 prev payload
   }
   pub struct TxnReport { written: usize, skipped: usize, rolled_back: bool }
   ```
2. 写后校验：`verify_identity(expected: &str)` 读回认证文件解析 uid/email，态枚举对齐 modeldeck——`Effective / IdentityMismatch / IdentityUnverified`。`IdentityMismatch` 一律自动 rollback。
3. 删除门槛硬化（落实 `lessons.md` 两条规则）：仅当 `copied == source_total && errors == 0 && verify_identity == Effective` 才允许删旧会话，否则 fail-closed 并在 `reason` 写明数字。
4. 命令返回结构化 `SwitchReport`，前端按 `rolled_back=true` 显式报错，不再只看 `replaced`。

**改动面**：`txn.rs`（新，~300 行）｜`switch.rs`｜`codebuddy_ide_session_sync.rs` 等 4 个 sync 模块｜`commands.rs`｜`api.ts`｜`AccountsView.vue`
**验证**：`tests/switch_txn_e2e.rs`（沙箱 `WB_SWITCH_HOME`）注入只读目录制造写失败 → 断言源数据 hash 前后一致、`rolled_back=true`
**影响**：切换耗时 +30~80 ms（多一次读回校验），可接受；磁盘多一份 `previous_snapshot`

### P0-2 用量预测

**方案**
1. 新增 `modules/forecast.rs`
   ```rust
   pub struct Forecast { per_day: f64, days_left: Option<f64>, deplete_at: Option<i64>, confidence: Confidence, basis_days: usize }
   pub fn forecast(account_id: &str, metric: Metric, window_days: usize) -> Forecast
   ```
   - 速率估计用 **中位数 + EWMA 双估计取小**（中位数抗单日爆发，EWMA 抓趋势）
   - `confidence`：`basis_days < 3` → `Insufficient`，UI 必须显示 `--`（竞品普遍在此瞎猜，我们不跟）
   - 余额口径：`信用余额 / credits_per_day`；token 口径：`token_stats` 日粒度
2. 命令 `account_forecast(metric, days)` 返回全账号数组（一次算完，避免 N 次 IPC）
3. UI：`AccountsView` 卡片余额右侧加 `≈Nd`（<3 天 hazard 红、<7 天 warning）；`TokensView` 效率 5 格中替换一格为「按当前速度耗尽日」

**改动面**：`forecast.rs`（新，~200 行）｜`commands.rs`｜`api.ts`｜2 个视图
**影响**：复用 `token_statistics` 的 5 分钟缓存，无额外 IO；纯内存聚合

### P0-3 成本折算

**方案**
1. 内置 `crates/wb-switch-core/assets/model-pricing.json`，字段 `{model, in, out, cache_read, cache_write, currency, effective_date}`，**随版本发布**（不引入 hourly sync 网络请求）
2. `modules/pricing.rs`：前缀匹配模型名（对齐 tokscale 的 8 级名解析），未命中 → `Unpriced`，从合计中**排除并单独计数**，绝不估
3. `token_statistics` 增加 `cost: { total, priced_tokens, unpriced_calls, currency }`
4. UI：8 指标替换一格为「等价成本 ¥」；调用明细加金额列；页脚标注「API 等价参考，非实际扣费」

**影响**：口径风险最高的一项。WorkBuddy 是积分制，成本只是参考值——**必须显式标注**，否则误导。价目表需人工随新模型更新，列入发版清单。

### P1-1 配额窗口统一

新增 `QuotaWindow { kind: Session | Weekly | Package | RateLimit, used, total, reset_at, source }`。
- `limits.rs` 的恢复时刻 → `RateLimit` 窗口
- `credits` 到期 → `Package` 窗口
- 官方若给 5h/7d → `Session/Weekly`；不给则**只做两类**，不虚构
UI 统一进度条 + 倒计时（`<1h` 显示 `mm:ss`，否则 `Nd hh`）。

### P1-2 健康评分

`health = 100 - Σ(惩罚)`，惩罚项：24h 限流事件 ×15、401/403 ×20、token 刷新失败 ×25、余额占比过低 ×10、最近切换失败 ×20，按时间指数衰减（半衰期 48h，caam 做法）。输出 0-100 + 三色。
UI：卡片序号左侧 6px 色块 + hover 明细。**不新增卡片高度**（遵守 `AGENTS.md`「同一信息只出现一次」）。

### P1-3 切换历史

`~/.wb-switch/switch_history.json`，保留 500 条：
```json
{"ts":0,"from":"uid","to":"uid","mode":"replace","reason":"manual|auto|ratelimit",
 "before":{"credits":0,"limits":[]},"after":{"credits":0},"result":"ok|rolled_back","cost_ms":0}
```
`events_list` 增加第四源 `switch`，`LogsView` 来源 TAB 自动多一列；`events_clear("switch")` 支持按源清空。

### P1-4 导出 + 环比

`token_statistics(days, refresh, compare)` 返回 `prev: {tokens, sessions, cost}`；命令 `export_stats(kind, format) -> path`（前端用 dialog 选路径）。CSV 列：日期 / 来源 / 模型 / 项目 / 输入 / 输出 / 缓存读 / 成本。

### P1-5 托盘读数

复用现有 tray：Windows `set_tooltip("最紧迫 ≈2.4d · 3 账号")`，macOS `set_title("2.4d")`。数据源用 P0-2 的 `account_forecast`，5 分钟节流。

### P1-6 限流驱动自动切换（高风控）

链路：`rate_limit_events` 信号 → 若 `auto_switch.enabled` 且受限账号 == 当前账号 且存在健康替代（score ≥70 且余额 >24h 用量）→ `switch_account(replace_sessions=true)` → 写历史 `reason=ratelimit`。
硬约束：全局 `RunFlagGuard` 互斥｜冷却 10 分钟｜首次开启二次确认｜会话续接失败则**不切**（宁可不切也不打断）。
**风险**：自动换号可能触发更严格风控，且用户不知情 → 默认关闭，UI 标注后果。

### P2 简述

- **多开隔离**：`shallow profile` 思路——只独立凭据目录，其余复用 HOME 软链。需先定产品问题：并行还是切换？
- **多设备聚合**：cc-switch 用 WebDAV/S3，codeburn 用局域网 `devices`。后者不破"零网络"约定，优先。
- **分支/PR 归因**：需从会话元数据提取 git 上下文，成本 M，收益仅对重度用户。
- **分位统计**：样本 ≥30 天再上，否则噪声。

## 7. Non-goals（明确不做）

| 不做 | 理由 |
| --- | --- |
| 30-50 工具统一口径 | 定位是 WorkBuddy 家族深度运营，不是通用账单工具；摊薄差异且需为每个工具写解析器 |
| 供应商 / 中转端点切换 | cc-switch（150k★）主场，进入即正面竞争，且与"共享登录态"哲学冲突 |
| MCP / Skills / Prompt 治理 | 同上，属 cc-switch 能力边界 |
| 排行榜 / 社交分享 | 账号数据敏感，与"零遥测"取向矛盾 |
| 团队多用户维度 | 个人工具，无 server 端 |
| 预算硬停 | 积分制非按量计费，硬停无意义，降级为预警 |

## 8. 潜在影响

| 维度 | 影响 | 缓解 |
| --- | --- | --- |
| **性能** | 预测与成本均为内存聚合，读现有缓存；切换多 30-80ms | 预测结果随 `token_statistics` 缓存 5 分钟；切换校验只读单文件 |
| **架构** | 新增 `txn / forecast / pricing` 三模块，全部无网络，符合"不新增网络请求"约定 | 每个模块单测 + 一个 `#[ignore]` live 测试 |
| **数据兼容** | 新增 3 个 JSON 文件需带 `schema_version` | 读时忽略未知字段，写时保留未知字段（前向兼容） |
| **风控** | 自动换号 + 限流驱动切换可能触发平台更严限流 | 默认关闭；冷却期；仅在"当前账号已受限"时触发 |
| **口径** | 成本为 API 等价参考值，非实际扣费 | UI 强制标注；未定价模型排除并单独计数 |
| **维护** | `model-pricing.json` 需随新模型更新 | 列入发版检查清单；提供手动刷新入口（不自动联网） |
| **信任** | P0-1 直接决定用户敢不敢用"完全同步" | 引入 `rolled_back` 显式报错 + 切换历史可回溯 |

## 9. 建议执行顺序

```
第 1 批（正确性）：P0-1 事务化 → P1-3 切换历史       ← 同一批改动，顺手完成
第 2 批（决策力）：P1-1 窗口统一 → P0-2 预测 → P0-3 成本
第 3 批（效率）  ：P1-2 健康评分 → P1-5 托盘 → P1-4 导出/环比
第 4 批（自动化）：P1-6 限流驱动切换 → P1-7 预警
第 5 批（战略）  ：P2 按产品决策取舍
```

第 1 批与第 2 批之间无依赖，可并行；P0-2 依赖 P1-1 提供正确分母，顺序不可颠倒。
